## 1. 이 문서의 목적과 읽는 기준

2026-11-10 선행 구현: 승인된 2번 방 배치와 물 획득·공격·회복을 연결했다. 원천은 손상 1/2 애니메이션을 각각 유지하고 3타 파괴 후 구슬만 F로 먹는다. 물 Space는 무소모, R은 회복 성공 시 물 1개만 소모한다. 첫 방 출구는 2번 방으로 이동하고 현재 마지막인 2번 출구에서 클리어한다. 저장 v2는 1/2번 방·섭취 중 상태를 복원하며 기존 v1 첫 방 저장도 읽는다. 최신 사용자 요청대로 무속성 적은 모든 공격에 큰 피해를 받는다. 큰 피해 15·낮은 피해 5·회복 20·HP100/30/40 등은 시험값이며 사용자 확정 숫자가 아니다.

지금까지 준비한 에셋을 실제 게임에 연결하기 위해 **무엇을 만들고, 어떤 순서로 구현하며, 무엇을 확인하면 완료인지** 정리한다. 이 문서 작성 자체가 게임 구현 완료를 뜻하지 않는다.

요구사항의 상태는 다음 세 가지로 구분한다.

- **확정**: 사용자가 정한 규칙 또는 승인한 최종 제작 범위. 구현 중 임의로 바꾸지 않는다.
- **설계안**: 기존 기획 또는 이 문서에서 제안하는 첫 구현 방식. 설정값·정책으로 분리하고 플레이 테스트 후 조정한다.
- **결정 필요**: 아직 정하지 않은 규칙. 정해진 사실처럼 코드에 숨겨 넣지 않는다. 필요한 구현 단계에 도달하기 전에 결정한다.

충돌하면 최신 사용자 지시와 확정 규칙을 먼저 따른다. 이 PRD의 최신 정리, [게임 기획](GAME_DESIGN.md), [방·보스 설계](STAGES_AND_BOSS.md), [장애물 설계](OBSTACLES_AND_HAZARDS.md)를 함께 확인한다. 기존 문서의 직접 사물 섭취·스킬 3회·무속성 무피해 같은 옛 설명은 아래 규칙으로 대체한다.

## 2. 플레이 경험과 핵심 반복

플레이어는 주변 원소 원천을 공격해 구슬을 얻고, 필요한 원소를 선택해 적의 약점을 공략한다. 원소를 보관하면서 기본 공격과 원소를 소모하는 고유 스킬을 구분해 사용한다. 전투와 환경 퍼즐을 해결해 다음 방으로 이동하고 마지막 원소 변환 보스를 처치한다.

1. 방의 적 원소·약점과 지형·퍼즐을 확인한다.
2. 항아리·장작·바람개비·돌무더기·전지를 공격해 파괴한다.
3. 방출된 구슬을 F로 먹어 원소별 보유 개수를 늘린다.
4. Q/E로 보유 원소를 선택한다. 몸 색·외형·HUD가 함께 바뀐다.
5. Space 기본 공격으로 전투하고 R 고유 스킬로 전투·환경 문제를 해결한다.
6. 방의 완료 조건을 달성해 출구를 열고, 총 10개 방을 진행한다.

성공 기준은 기능을 각각 시연하는 데서 끝나지 않고, **원소 획득 → 선택 → 전투·퍼즐 → 다음 방 → 보스 → 최종 출구**가 한 실행에서 이어지는 것이다.

### 3.3 이번 제작에서 제외하는 것

온라인·멀티플레이, 절차적 맵 생성, 원소 합성, 장비 강화, 별도 성장 트리, 원소별 독립 AI 추가는 범위에 넣지 않는다. 흙 충격파·번개 기절·흙으로 구멍 메우기 역시 현재 능력에 자동 추가하지 않는다. 기존의 세션 간 저장 제외 설계안은 최신 타이틀/이어하기 사용자 요청으로 변경했다.

### 타이틀·이어하기 추가 요구사항

- 사용자 확정: 제작한 타이틀 이미지 위에 왼쪽 이어하기/가운데 새게임 시작/오른쪽 종료 버튼을 둔다. 저장이 없으면 이어하기는 클릭할 수 없고, 있으면 아래에 스테이지 번호를 표시한다.
- 구현: `main.py`는 타이틀부터 시작한다. 마우스 클릭과 좌우/A/D/Tab 선택·Enter/Space를 지원한다. 현재 구현된 첫 방의 저장만 지원하며 스테이지 표시는 1번이다.
- 초기 운영안: 2초 간격과 일시정지/타이틀 복귀/종료 시 자동 저장한다. 위치·HP·적 생존/HP·비행 탄환·공격 상태를 복원하고, 새게임 시작은 진행을 초기화한다. 사망 시 마지막 살아 있는 저장을 보존하며 첫 방 클리어 후 이어하기를 비운다. 저장은 버전 검증·원자 교체를 사용하고 로컬 `saves/continue.json`을 Git에서 제외한다. 손상되거나 지원하지 않는 저장은 이어하기를 비활성화한다.

## 4. 기능 요구사항

### FR-01. 실행·화면·플레이어 이동

**확정**

- Python/pico2d로 본게임을 만든다.
- WASD로 이동하고 마지막 이동 방향으로 공격한다. 마우스 조준은 사용하지 않는다.
- 원소를 선택하면 해당 몸 색과 구분 외형을 표시한다.
- 대기·이동·공격·섭취 중 몸통 크기와 기준점이 흔들리지 않게 한다.

**설계안**

- 첫 대상 환경은 현재 데스크톱·노트북의 Windows 키보드 실행이다. 실제 Python/pico2d 버전은 M0 실행 검증 후 고정한다.
- 4방향 바라보기, 시작 방향 아래. 대각선 이동 속도는 정규화하고 마지막으로 누른 이동키 방향을 바라본다.
- 기존 30×30 기본 맵을 첫 테스트 방으로 사용한다. 모든 방의 크기를 30×30으로 확정하는 것은 아니다.
- 1280×720을 첫 화면 크기로 시험한다. 최종 카메라 범위와 월드 배율은 별도 조정한다. 기존 16×9칸 화면은 구도 시안이지 고정 카메라 요구사항이 아니다.

**완료 조건**: 게임 창에서 대기·걷기가 전환되고, 대각선 이동이 빨라지지 않으며, 키를 놓아도 마지막 방향이 유지된다. 고정 벽을 통과하지 않고 방향·동작 전환 시 몸통이 튀지 않는다.

### FR-02. 조작과 일시정지

| 입력 | 동작 | 상태 |
| --- | --- | --- |
| WASD | 이동 및 마지막 방향 갱신 | 확정 |
| Q / E | 보유한 이전 / 다음 원소 종류 선택 | 확정 |
| Space | 현재 원소 기본 공격, 원소 개수 소모 없음 | 확정 |
| R | 현재 원소 고유 스킬, 정상 발동 시 그 원소 1개 소모 | 확정 |
| F | 방출된 원소 구슬 섭취 | 확정 |
| Esc | 일시정지 메뉴, 메뉴 안의 현재 방 재시작 | 재시작 위치 확정. 메뉴 동작 세부는 설계안 |

R을 재시작 키로 사용하지 않는다. Q/E/R/F는 키 자동 반복으로 여러 번 처리하지 않는 설계안이다. 일시정지 중 이동·공격·화상·스킬·보스 변신·원천 재공급·애니메이션의 게임 시간을 함께 멈추고, 재개 시 정지한 시간이 한꺼번에 진행되지 않게 한다.

**완료 조건**: 메뉴에서 재개·현재 방 재시작·종료를 구분할 수 있고, 일시정지로 체력이나 타이머가 진행되지 않는다. 게임 창 종료 요청도 정상 처리한다.

### FR-03. 원천 파괴와 구슬 획득

**확정**

- 물 항아리·불 장작·바람개비·돌무더기·전지를 직접 먹지 않는다. **공격으로 파괴한 뒤 나온 구슬만 F로 먹는다.**
- 약점이 아닌 공격은 정확히 3타에 파괴한다. 같은 원소와 무속성 공격도 이 3타 규칙에 포함한다.
- 약점 공격은 현재 손상 정도와 관계없이 1타에 파괴한다.
- 첫째·둘째 타격 뒤 손상 상태는 다음 공격까지 유지된다. 각 손상 상태의 대기 애니메이션은 계속 반복한다.
- 파괴·방출은 한 번만 실행하고 이후 구슬을 유지한다. 원소 종류와 관계없이 구슬의 표시 지름을 같게 한다. 기존 96px는 미리보기 규격이며 게임 월드의 최종 표시 수치는 아니다.
- 타격 흔들림이 끝나면 원천은 원래 물리 기준점으로 돌아온다.

| 원천 | 1타 파괴 약점 | 나머지 공격 |
| --- | --- | --- |
| 물 항아리 | 번개 | 3타 |
| 불 장작 | 물 | 3타 |
| 바람개비 | 불 | 3타 |
| 돌무더기 | 바람 | 3타 |
| 전지 | 흙 | 3타 |

상태는 `정상 → 손상1 → 손상2 → 파괴/방출 → 구슬 → 섭취 완료`로 구분한다. 약점이면 정상·손상1·손상2 어디서든 파괴/방출로 바로 간다.

첫 구현은 Space의 단일 타격으로 검증한다. 구슬 드롭 수, 원천 재생성 세부, R 효과·지속 피해를 원천 타격으로 인정하는 방법은 결정 필요 항목이다. 한 발의 중복 충돌로 여러 타격이나 여러 구슬이 생기지 않게 하는 것은 구현 요구사항이다.

**완료 조건**: 공격 원소 6종 × 원천 5종의 30조합에서 3타/1타가 맞고, 두 손상 단계에서 실제 화면 픽셀이 계속 변한다. 오래 기다려도 손상이 저절로 진행·초기화되지 않는다. F를 반복해도 같은 구슬을 중복 획득하지 않는다.

### FR-04. 원소 보관·선택·소모

**확정**

- 먹은 원소는 종류별 개수로 쌓이고 다른 원소도 함께 보관한다.
- Q/E는 개수가 있는 종류 사이에서 선택한다. 0개인 종류는 선택할 수 없다.
- 선택 원소가 몸 색·외형·HUD·Space·R을 결정한다.
- Space는 개수를 줄이지 않는다. 성공한 R은 발동한 원소에서 정확히 1개를 뺀다.
- 보유 종류가 없으면 무속성이다. 무속성은 보관 가능한 여섯 번째 원소가 아니다.
- 생성된 효과와 투사체는 발동 당시 원소를 유지한다. 선택 변경·마지막 원소 소모로 이미 만든 효과가 다른 원소로 바뀌지 않는다.

**설계안**: 선택 순서는 물→불→바람→흙→번개, F 섭취 직후 해당 원소 선택, 선택 종류 소진 시 다음 보유 종류 자동 선택으로 시작한다. 발동 자체가 실패한 R은 소모하지 않는다. 불 발사 후 빗나감 등 발동 성공과 적중 실패는 구분한다.

**완료 조건**: 불 2개·물 1개에서 불 Space는 불 2개를 유지하고, 불 R 성공은 1개만 줄인다. 마지막 불을 써 외형이 바뀌어도 이미 발사한 불 효과는 불로 남는다. 종류가 하나일 때 Q/E는 선택을 유지하며 개수가 음수가 되지 않는다.

### FR-05. 기본 공격과 원소 적 상성

**확정**

- 원소 공격은 아래의 정확한 1대1 순환만 원소 적에게 피해와 공격 효과를 준다.
- 같은 원소를 포함한 나머지는 **피해 0, 화상·넉백·연쇄 등 공격 효과 0**이다. 차단된 공격으로 적을 구멍에 떨어뜨리지 않는다.
- **무속성 플레이어 기본 공격은 별도 예외**로, 다섯 적 원소 모두에 0보다 큰 낮은 피해와 약한 넉백을 준다. 바람 R의 강한 넉백과 구분한다.
- **무속성 적은 무속성·다섯 원소 공격 모두에 큰 피해**를 받는다. 큰 피해 15는 시험값이다. 이 대상 예외는 원소 적의 상성 차단을 바꾸지 않는다. 무속성 기본 공격의 약한 넉백은 유지한다.
- 원소별 Space 공격과 R 고유 스킬은 별개이다. 물 Space를 회복으로 처리하지 않는다.

| 공격 원소 | 피해·공격 효과가 허용되는 적 원소 |
| --- | --- |
| 물 | 불 |
| 불 | 바람 |
| 바람 | 흙 |
| 흙 | 번개 |
| 번개 | 물 |

**설계안**: 투사체는 첫 적 또는 벽과 충돌하면 제거한다. 공격 시작에 원소·방향을 기록하고, 지정 프레임에서 한 번 발사한다. 피해 적용 전 대상 분류와 상성을 검사하고, 통과한 경우에만 피해·후속 효과를 적용한다. 적 공격에 대해 플레이어가 원소 면역이 되는 규칙은 두지 않는다.

원천 오브젝트의 3타/약점 1타, 원소 적의 상성, 무속성 적의 모든 공격 큰 피해, 환경 퍼즐 반응은 각각 별도 판정이다.

**완료 조건**: 원소 공격 25조합 중 5개만 허용되고 20개는 완전히 차단된다. 무속성 기본 공격은 다섯 원소 적에게 낮은 피해·약한 넉백을 준다. 무속성 적에게는 여섯 공격 모두 큰 피해이며 약한 넉백은 무속성 기본 공격에만 적용한다. 프레임 이벤트·충돌이 반복 호출돼도 한 발이 같은 대상에게 중복 피해를 주지 않는다.

### FR-06. 원소별 R 고유 스킬

| 원소 | 확정 역할 | 첫 구현 설계안 | 발동 실패 판단의 설계안 |
| --- | --- | --- | --- |
| 불 | 지속 피해 | 전방 화염탄, 바람 적에게 화상. 직접 피해 없이 주기 피해, 재적중은 지속시간 갱신 | 발사 자체가 불가능한 경우. 발사 후 빗나감은 성공 |
| 물 | 자기 회복 | 최대 체력을 넘지 않는 즉시 회복. 적 상성 필터와 분리 | 이미 최대 체력 |
| 바람 | 강한 넉백 | 전방 범위의 흙 적을 밀고 벽 앞에서 멈춤. 퍼즐 돌은 환경 대상으로 별도 처리 | 대상 없음은 사용 성공으로 처리하는 초기안 |
| 흙 | 지형 생성 | 유효한 빈 위치에 임시 벽. 이동·직선 탄환 차단, 유지시간 후 제거 | 벽·캐릭터·원천·출구와 겹쳐 배치 불가 |
| 번개 | 다중 대상 연쇄 | 첫 물 적부터 근처의 다른 물 적으로 연결. 대상 중복 타격 방지 | 첫 유효 대상이 없음 |

스킬은 원소·대상·위치를 기록하고 유효성을 확인한 뒤 효과 생성과 소모를 한 번 처리한다. 물·흙의 비공격 기능에 적 상성 필터를 적용해 막지 않는다. 흙벽의 물리 충돌도 적 색으로 무시하지 않는다.

**완료 조건**: 다섯 역할을 게임 안에서 각각 수행하고 소모가 정확하다. 불은 틱 수가 렌더 프레임 수에 종속되지 않고, 바람은 벽을 통과시키지 않으며, 흙은 잘못된 위치에 생성하지 않는다. 번개는 허용되지 않은 원소로 이어지거나 같은 대상을 중복 타격하지 않는다.

### FR-07. 적 AI·피격·처치

두 행동형을 공통 구현하고 원소·외형·수치를 데이터로 분리하는 설계안이다.

| 유형 | 첫 행동 설계안 | 공격 동작과 판정 |
| --- | --- | --- |
| 근접 추격형 | 플레이어 추격, 고정 장애물의 우회 지점 사용, 임시 벽에 막히면 대기 | 접촉 공격. 주먹 애니메이션 때문에 추가 사거리·광역 공격을 자동 부여하지 않음 |
| 원거리 사격형 | 제자리 대기→방향/공격 예고→직선 탄환→재사용 대기 | 공격 애니메이션 이벤트에서 한 번 발사. 준비된 이동 시트가 AI 이동 요구사항을 뜻하지 않음 |

- 플레이어와 적의 체력·피격·무적 시간·처치 상태를 분리한다.
- 일반 적 체력이 0이면 공격을 종료하고 남은 적 수에서 한 번만 뺀다.
- 추락 처치를 채택하면 같은 적이 피격·추락으로 중복 집계되지 않게 한다.
- 무속성 적의 외형·동작은 준비됐지만, 원소 공격 수용 규칙을 결정하기 전에는 실제 전투 방의 필수 적으로 배치하지 않는 개발 방식을 제안한다. 원소 적으로 전투 기능을 먼저 검증할 수 있다.

**완료 조건**: 추격형은 이동·접촉 공격, 사격형은 예고·발사·대기를 수행한다. 같은 시트의 공격 프레임을 오래 보여도 탄환이 반복 생성되지 않는다. 처치된 적의 공격과 충돌이 남지 않는다.

### FR-08. 벽·구멍·가시와 넉백

**확정**: 구멍·낭떠러지, 벽, 가시를 구분한다. 플레이어와 적 모두 구멍에 떨어질 수 있어야 한다. 상성 차단된 공격은 넉백·추락을 유발하지 않는다. 빈 기본 맵은 보존하고 장애물 맵은 별도 데이터로 사용한다.

**설계안**

- 고정 벽·임시 흙벽은 이동과 직선 탄환을 막는다.
- 구멍은 벽이 아니라 바닥 부재로 처리하고 발밑 기준점의 진입을 검사한다.
- 플레이어는 일부 피해 후 마지막 안전 위치로 복귀, 일반 적은 추락 처치부터 시험한다.
- 안전 위치·시작점·구슬/원천 재공급 지점은 위험 구역과 겹치지 않게 한다.
- 가시는 시간 간격을 둔 접촉 피해를 시험한다. 대상·피해량·간격은 결정 필요다.
- 적의 자율 이동 시 위험 회피와 넉백 등 강제 이동에 의한 추락을 구분한다.

보스의 추락 결과는 미확정이다. 일반 적 즉사나 보스 면역을 자동으로 적용하지 않는다. 흙벽으로 구멍을 메우거나 다리를 만드는 기능도 추가하지 않는다.

**완료 조건**: 벽 충돌·추락·가시 접촉이 서로 다른 결과를 내며, 복귀 직후 무한 추락하지 않는다. 유효한 넉백과 차단된 공격의 결과를 구분한다. 일반 적 추락 때문에 출구 개방이 영구적으로 막히지 않는다.

### FR-09. 환경 퍼즐과 재시도

| 원소 | 장치와 해결 방식의 설계안 |
| --- | --- |
| 불 | R 화염탄으로 덩굴을 태워 통로 열기 |
| 물 | Space 물 공격으로 바닥 불길 끄기 |
| 바람 | R로 퍼즐 돌을 밀어 압력 발판 누르기 |
| 흙 | 통로 원천을 파괴해 길을 연 뒤 구슬 섭취, R 흙벽으로 사격선 차단 |
| 번개 | R로 전도체 3개를 연결해 전력 문 열기 |

원소 환경 퍼즐은 최종 범위에 포함한다. 적 상성과 환경 대상의 반응을 분리한다. 예전 ‘돌을 바로 먹어 통로 열기’는 파괴→구슬 섭취 흐름으로 바꾼다. 통로의 물리 장애물 제거 시점은 원천 파괴 완료로 잡는 초기안이다.

퍼즐 완료·열린 문은 현재 방에서 유지하고, 필수 원소를 소진해도 다시 얻을 경로를 둔다. 퍼즐 돌이 원소 원천을 겸하는지와 재생성·중복 개체 처리 방식은 퍼즐 구현 전 결정한다. 장치·원천·적이 같은 그림이나 원소를 써도 대상 역할을 데이터로 구분한다.

**완료 조건**: 다섯 환경 반응을 각각 해결할 수 있고, 필요한 원소 소진·돌의 잘못된 이동·흙벽 만료 뒤에도 재시도할 수 있다. 잘못 생성된 중복 퍼즐 돌로 문이 우연히 열리지 않는다.

### FR-10. 방 진행·보스·재시작

**확정 범위**: 일반 방 9개와 원소 변환 보스 방 1개, 총 10개 방을 만든다.

**진행 설계안**

- 일반 방은 적 전멸과 필수 퍼즐 완료를 함께 확인해 출구를 연다. 2026-11-09 요청에 따라 첫 방은 기본원소를 무속성으로 해석한 근접 적 2마리·원거리 적 2마리와 가시·낭떠러지를 먼저 배치한다. 최신 사용자 그림에 맞춰 아래 시작 섬과 위쪽 큰 구역을 좁은 길로 연결하고, 길 양옆과 바닥 바깥은 낭떠러지, 위쪽 중앙 빗금 부분은 벽으로 둔다. 큰 구역에 진입하면 근접 적이 추격한다. [지도 시안](../../assets/maps/room-01/README.md)과 독립 HTML 이동·추격 시연은 준비했으며, 20×22칸·폭 2칸 길·좌표·속도·진입 후 추격 유지·출구는 초안이다. Python/pico2d 본게임은 미구현이다.
- 2026-11-10 승인된 2번 방은 [물의 유적](../../assets/maps/room-02/README.md)으로 변경하고 게임/저장에 연결했다. 무속성 2/불 2, 물 원천 2개의 배치를 유지하며 원천 공격→방출 구슬 F 섭취→물로 불 적 공략·R 회복을 구현했다. 기존 2번 덩굴 정원안은 대체한다. 3~6번의 원소 학습 순서는 재검토하며 7~9번은 조합, 10번은 보스다. 3번 이후는 미구현이다.
- 정상 방 전환은 체력·원소별 개수·선택을 유지한다.
- 사망과 Esc의 현재 방 재시작은 현재 방의 적·원천·구슬·퍼즐·보스를 초기화한다. 체력은 최대, 보관함은 비우고 무속성으로 시작한다.
- 방 이동·재시작 때 이전 방의 탄환·화상·임시 벽·대기 중 공격 이벤트를 정리한다. 이벤트가 이전 방을 다시 수정하지 않게 한다.

**보스 설계안**

- 불→바람→흙→번개→물로 변신하고 체력은 유지한다. 현재 원소·약점과 다음 변신을 예고한다.
- 각 형태의 예고 공격은 [방·보스 설계](STAGES_AND_BOSS.md)의 부채꼴 탄환·돌진·낙석·전격탄·물방울 패턴부터 구현한다.
- 투사체는 보스에게 적중한 시점의 현재 원소로 판정한다. 발사체 자신의 원소는 발사 당시 것을 유지한다.
- 화상은 틱마다 보스 상성을 검사하고 바람 상태가 끝나면 해제한다. 번개는 같은 보스를 연쇄로 여러 번 때리지 않는다.
- 변신 시 남은 보스 예고·공격을 정리하고, 필요한 원소를 다시 확보할 수 있게 공급한다.
- 보스 처치 후 최종 출구 도달로 클리어한다. 보스 방 실패 시 첫 방으로 돌아가지 않고 보스 방을 재시작한다.

**완료 조건**: 1번부터 10번까지 한 실행으로 진행하고 보스 처치·최종 출구에서 클리어된다. 각 방 및 보스전 재시작이 정상이며, 변신 직전 발사한 탄환도 적중 시점 상성을 따른다.

### FR-11. HUD·피드백

첫 UI 설계안은 다음과 같다.

- 체력, 현재 방, 남은 적 수, 선택 원소, 원소별 보유 개수와 Q/E 안내를 표시한다.
- 원소 적은 원소 이름·외형·약점을 함께 표시한다. 무속성 적은 모든 공격에 큰 피해를 받으므로 특정 약점 원소를 표시하지 않는다.
- 가까운 구슬의 F 안내, 원천 손상·구슬 방출, 적중·상성 차단, 스킬 발동 실패·회복·처치를 구분한다.
- 흙벽 배치 유효성, 퍼즐 완료·출구 개방, 보스 현재/다음 원소를 확인할 수 있게 한다.
- 한글 글꼴을 정상 표시하고, 색뿐 아니라 형태·문자로 원소와 위험을 구분한다.

**완료 조건**: 보관함·현재 외형·HUD가 같은 상태를 보여주며, 사용자가 공격 차단과 적중, 스킬 실패와 원소 소모를 구분할 수 있다.

## 5. 기술·에셋 연결 요구사항

다음은 구현 구조의 제안이다. 파일 이름은 첫 구현에서 조정할 수 있으나 판정 책임은 분리한다.

| 모듈 | 책임 |
| --- | --- |
| 실행/장면 | 초기화·입력·업데이트·그리기·종료, 플레이·일시정지·클리어 전환 |
| 월드/맵 | 타일·고정 벽·위험·스폰·출구·안전 위치 |
| 플레이어/보관함 | 이동·방향·행동 상태와 종류별 개수·선택 |
| 공격/스킬 | 발사 당시 정보, 적/원천/환경별 필터, 피해·효과·소모 |
| 원천/구슬 | 내구도 상태, 단발 방출, 섭취, 재공급 |
| 적/보스 | 공통 행동형, 원소 데이터, 예고·공격·변신·처치 |
| 퍼즐/진행 | 장치 상태, 방 완료 조건, 전환·현재 방 재시작 |
| 리소스/애니메이션 | PNG/JSON 캐시, 클립·피벗·프레임 이벤트 |
| UI/설정 | HUD, 메뉴, 조절 가능한 수치·개발용 확인 표시 |

필수 연결 조건은 다음과 같다.

1. **현재 작업 폴더와 무관한 경로**: 소스 위치 기준으로 저장소 루트를 찾아 에셋을 읽는다. PC 절대 경로를 코드·JSON에 넣지 않는다. 한글·공백 경로에서 실행을 확인한다.
2. **설치와 실행 재현**: M0에서 검증한 Python/pico2d 버전·의존성·설치/실행 명령을 기록한다. `src/`에 실행 가능한 진입점을 만들고, 목표 실행 명령은 `python -m src.main`으로 제안한다. 현재 이 명령이 동작하는 것은 아니다.
3. **원본 시트 재사용**: 플레이어 128px 칸·피벗 (64,114), 적 160px 칸·루트 (80,138), 투사체 160px 칸·중심 (80,80)을 각 JSON과 함께 읽는다. 서로 다른 칸 크기를 하나로 가정하지 않는다.
4. **고정 기준점**: 물리 위치·충돌 영역과 그리기 피벗을 분리한다. 매 프레임의 귀·발·불꽃 외곽으로 확대·축소·재중심화하지 않는다. 뒤를 볼 때 얼굴을 추가하거나 몸 색을 어둡게 바꾸지 않는다.
5. **좌표 규약**: JSON의 위쪽 원점 프레임 좌표와 `pico2dClip`의 아래쪽 원점 좌표를 구분한다. 물리 좌표·화면 좌표·카메라 변환을 한 곳에서 처리한다.
6. **안정적인 시간 처리**: 첫 프레임·역행 시간·비정상 dt를 방어한다. 이동·공격·지속 피해·재공급은 경과 시간으로 처리하며 저프레임에서 이벤트가 누락·중복되지 않게 한다.
7. **단발 이벤트 보장**: 발사·섭취·스킬 소모·원천 방출·처치를 행동 인스턴스별로 한 번만 실행한다. 애니메이션 프레임을 단순 비교해 매 업데이트마다 반복 실행하지 않는다.
8. **리소스 수명**: 이미지를 프레임마다 디스크에서 다시 읽지 않는다. 방 전환·재시작에 이전 방 객체와 타이머를 정리하고, 유효한 에셋이 없으면 누락 경로를 알 수 있게 한다.
9. **제작 도구와 게임 분리**: Pillow·NumPy는 제작·검증 도구 의존성이다. HTML 재생기·이미지 생성 도구·개인 pixelfx 설치가 게임 실행의 필수 조건이 되지 않게 한다.
10. **논리 검증 분리**: 상성·원천 내구도·보관함·소모·방 초기화는 가능하면 그래픽 창 없이 검사할 수 있게 구성한다. 렌더링·피벗·입력은 실제 pico2d 창에서 검증한다.

## 6. 첫 구현에 사용할 시험값

아래는 전부 **미확정 시험값**이다. 코드 곳곳에 상수로 흩어 넣지 않고 설정 데이터로 모은다. 밸런스 확정이나 사용자 승인 수치로 인용하지 않는다.

| 항목 | 첫 시험값/현재 제안 |
| --- | --- |
| 플레이어 최대 체력·이동·피격 무적 | 100 / 220px/s / 0.7초 |
| 원소 기본 공격 | 기본 10 × 약점 1.5 = 15, 간격 0.4초, 사거리 320px |
| 무속성 기본 공격 | 원소 적 피해 5·무속성 적 피해 15, 간격 0.5초, 사거리 160px, 탄속 280px/s (기획 초기안; 현재 실행값은 `src/combat.py`) |
| 무속성 약한 넉백 | 일반 적 12px·보스 4px, 0.1초 |
| 물 R | 체력 20 회복 |
| 불 R | 화상 3초, 초당 기본 4 × 약점 1.5 = 6, 중첩 없이 갱신 |
| 바람 R | 전방 90도·반경 160px, 최대 96px 넉백 |
| 흙 R | 앞 96px, 96×32px 벽, 유지 4초, 동시에 1개 |
| 번개 R | 첫 대상 320px, 다음 대상 반경 200px, 최대 3명, 대상당 15 |
| 일반 적 | 근접 체력 30·속도 110px/s, 원거리 체력 40, 적 공격 피해 10 |
| 재공급 | 일반 방 8초, 보스 방 3초. 파괴·섭취 이후 정확한 기산점은 추가 결정 |
| 보스 | 체력 450, 형태 유지 8초, 마지막 1.5초 예고, 변신 후 1초 공격 휴식 |
| 애니메이션 이벤트 | 플레이어 공격 3번 프레임, 섭취 4번 프레임, 적 공격 3번 프레임 |

프레임 번호는 JSON과 같이 0부터 센다. 예를 들어 12fps의 3번 프레임 진입은 약 0.25초이다. 원소 원천의 **3타/약점 1타**는 이 시험값 표와 달리 사용자 확정 규칙이다.

## 7. 구현 순서와 단계별 완료 기준

현재 모든 본게임 단계는 미착수다. 달력보다 아래 의존 순서로 진행하고, 각 단계의 완료를 실제 실행·검사로 확인한다.

| 단계 | 구현 결과 | 이 단계가 끝났다는 기준 |
| --- | --- | --- |
| M0 · 실행 골격 | Python/pico2d 환경, 진입점, 창·루프·종료, PNG/JSON 로더 | 문서의 설치/실행 명령으로 창과 캐릭터가 표시되고 정상 종료. 버전·경로 기록 |
| M1 · 이동 테스트 방 | 기본 맵 1개, WASD·마지막 방향·벽 충돌, 대기/걷기, Esc 정지 | 이동·대각선·방향·벽·피벗·일시정지를 실제 창에서 확인 |
| M2 · 원소 획득/선택 | 원천 5종, 3타/약점 1타, 손상 루프·구슬·F, 보관함·Q/E·외형/HUD | 구슬 1개를 한 번 획득하고 종류별 개수 누적. 손상 상태가 다음 공격까지 움직임 유지 |
| M3 · 전투/스킬 | Space 6종 투사체, 5×5 상성, 적 두 AI, 체력·처치, R 5종·소모 | 허용/차단·무속성 예외·스킬 성공/실패·마지막 원소 소모를 한 방에서 검증 |
| M4 · 지형/퍼즐 | 구멍·가시·넉백, 흙벽 충돌, 환경 퍼즐 5종과 재시도 | 플레이어·적 추락 및 선택한 피해 정책 작동. 필수 원소 소진 후에도 재진행 가능 |
| M5 · 10개 방/보스 | 일반 방 9개 데이터, 보스 방·변신·패턴·공급, 출구·클리어 | 한 실행으로 10개 방 완료. 보스 변신 시점의 상성·화상·재시작 검증 |
| M6 · 시연 품질 | HUD·음향·연출 보완, 수치 조정, 두 PC 실행·회귀 검사 | 깨끗한 복제본의 노트북에서도 실행하고 정상 진행·사망·재시작·클리어 확인 |

**첫 착수 작업은 M0와 M1이다.** 처음부터 10개 방을 동시에 만들지 않고, 테스트 방 하나를 실행 가능한 기반으로 만든다. M2의 원천 피격 검증에는 Space 단일 탄환과 시험용 공격 원소 선택 장치를 먼저 연결할 수 있다. 이는 개발용 확인 장치이며 최종 조작키에 추가하지 않는다.

M3 완료 시점의 첫 핵심 시연은 다음과 같다.

> 테스트 방에서 물 원천을 무속성으로 3번 공격한다 → 방출된 물 구슬을 F로 먹는다 → 물 외형/HUD로 바뀐다 → 물 Space로 불 적에게 피해를 준다 → 물 R로 자신을 회복하고 물 1개를 소모한다 → 원소 소진 뒤 무속성으로 돌아가도 이미 만든 효과는 올바르게 남는다.

회복 시연은 체력이 감소한 상태에서 진행한다. 이 시연과 함께 서로 다른 원소를 누적 보관하고 Q/E로 전환하는 경우도 확인한다.
